# KMS 관리 콘솔·사용자 포털 구현 보고서

작성일: 2026-09-24

## 요약

- 선택한 미리보기의 SAP Fundamental Styles, 무채색 다크 테마, 관리자 사이드 메뉴, 사용자 상단 메뉴, 목록·상세 분할 화면을 실제 서비스 UI로 구현했습니다.
- `frontend`를 Spring Boot JAR에 포함해 `/console/`에서 제공합니다. 화면 데이터와 변경 작업은 실제 API를 사용합니다.
- 개인별 관리자 세션 로그인·CSRF·변경 작업 MFA를 연결했습니다. 일반 사용자 서비스 접근 정책, CSR 접수·검토·발급·다운로드·이력 저장 기능을 추가했습니다.
- 서버 테스트 **70개**, 프런트엔드 테스트 **4개** 통과. JAR 빌드 성공. 브라우저에서 주요 업무 흐름·화면 전환·390px 모바일 배치를 검증했습니다.
- 설정 화면은 **현재 적용값 조회와 운영 절차 안내**입니다. HSM·보호 키·외부 계정 정책·백업 복원은 기존 운영 절차를 유지합니다. 운영 배포는 수행하지 않았습니다.

## 서버 변경

`console` 패키지에 세션 인증 필터, 로그인·설정 컨트롤러, 사용자 정책 로더, 포털 서비스·컨트롤러, `/console/` 진입 컨트롤러를 추가했습니다. 기존 KMS 인증에는 토큰 해시 기반 인증 진입점과 비밀을 제외한 관리자 메타데이터 조회를 추가했습니다. 기존 관리자 필터와 컨트롤러의 역할·MFA·키 범위 검사를 그대로 통과해야 합니다.

세션에는 토큰 원문 대신 해시를 저장합니다. 브라우저 저장소에는 토큰을 남기지 않습니다. 로그인 시 세션을 교체하며 유휴 15분·최대 8시간을 적용합니다. HttpOnly/SameSite=Strict 쿠키, HTTPS의 Secure 쿠키, CSRF 토큰, 동일 출처 검사, 기본 CSP를 사용합니다. 운영 모드 브라우저 API는 HTTPS를 요구합니다. 관리자·사용자 정책 파일은 요청마다 다시 검사하여 토큰 회전·소유권 변경을 반영합니다. 기존 Bearer API 호출은 유지합니다.

사용자 정책은 `CASTRELSIGN_PORTAL_USERS_FILE`로 지정합니다. 서비스는 Application principal입니다. 인증서 요청은 `portal_certificate_requests`, 활동은 `portal_activity`에 저장합니다. 유효한 P-256 CSR/CN/서명을 검사하고 개인키 입력, 64 KiB 초과, 중복 대기 요청을 거부합니다. 승인 직전 현재 사용자 정책과 서비스 상태를 다시 검사합니다. 발급에는 기존 CA·KMS 서명 경로를 사용합니다. 기존 인증서는 이전 버전으로 전환되며 처리 완료 후 CSR 원문은 비웁니다.

## 검증 결과

| 검증 | 결과 |
| --- | --- |
| `gradlew test bootJar --no-daemon` | 성공, 서버 70개 테스트·실제 프런트엔드 포함 JAR |
| 최종 UI 수정 후 `gradlew bootJar --no-daemon -x frontendInstall` | 성공, 이미 설치·고정된 의존성 사용, 프런트엔드 재빌드 포함 |
| `frontend: npm test` | 4개 통과: CSRF/MFA 전달, multipart 경계, 만료 세션/MFA 오류 구분, CSV 이스케이프 |
| 신규 서버 통합 테스트 | 8개 통과: 세션·로그아웃·CSRF·교차 출처·사용자 격리·CSR 승인·소유권 재검사·MFA 재사용·역할 회수·토큰 회전 |
| 관리자 브라우저 검증 | 키 버전 준비 성공, 화면·하위 탭 로딩, 실제 설정·목록 표시 |
| 사용자 업무 흐름 | CSR 접수 → 관리자 사유 입력·승인 → ACTIVE 인증서 표시 → 다운로드 요청·수령 이력 기록 |
| 반응형·접근성 | 1440×960, 390×844 검증, 페이지 가로 넘침 없음, 표 내부 스크롤, 키보드 포커스·대화상자 복원 |
| 디자인 비교 | 원본 미리보기와 전체·상세 이미지 비교 완료. [QA 기록](frontend/design-qa.md) |

브라우저 검증은 `build/console-smoke`의 격리된 개발 저장소와 합성 계정을 사용했습니다. 서버는 `127.0.0.1:8444`에만 바인딩했습니다. 이 검증 서버의 HTTP는 로컬 테스트용이며 운영 HTTPS 기본값을 변경하지 않았습니다. 재시작 후 실제 JAR에서 준비된 키 버전, APPROVED 요청, 발급 인증서가 유지되는 것도 확인했습니다.

## 제약과 검증하지 않은 환경

- 외부 정책 파일 편집, HSM 장비 설정, wrapping key 회전, 온라인 백업·복원은 UI 변경 API를 추가하지 않았습니다. 기존 운영 절차를 안내합니다.
- OIDC/SSO, 비밀번호 재설정, 사용자별 MFA 등록 화면, 범용 암·복호화 API는 추가하지 않았습니다.
- HSM 실장비·운영 프록시·외부 인증서 신뢰 배포·실제 에이전트 업데이트 배포는 이번 브라우저 테스트 대상이 아닙니다. 기존 서버 회귀 테스트는 통과했습니다.
- 브라우저의 다운로드 이벤트 관측은 제한되었습니다. PEM 응답 본문은 서버 통합 테스트로 확인했고, UI 클릭 후 서버 수령 이력과 콘솔 오류 없음도 확인했습니다. OS 다운로드 폴더에 최종 저장되는 경로는 별도 확인 대상입니다.
- 감사 조회는 페이지 단위, 포털 요청·이력은 최근 200건입니다. 내보내기도 화면의 조회 범위를 사용합니다.
- 서버 재시작 시 브라우저 세션은 종료됩니다. 다시 로그인하면 저장된 업무 데이터는 유지됩니다.

설치·사용자 정책 예시는 [프런트엔드 README](frontend/README.md), 운영 보안 구성은 [KMS 운영 가이드](KMS_OPERATIONS.md)를 참고하세요.
