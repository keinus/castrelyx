# FlowTransformer 논문 기준 Laya 비교 실험

> **2026-10-06 중단 후 보고 완료.** Laya 2회와 비교군 119회의 완료 성적을 종합한 [중단 시점 종합 보고서](STOPPED_REPORT.ko.md)를 확인한다. 세 번째 Laya 반복은 중단 상태다. 학습을 재개하지 않고 기존 체크포인트 9개 설정의 추론 속도와 두 번째 Laya의 지연을 추가 측정했다. [속도 결과](speed/results.csv)와 [원시 측정값](speed/verified_summary.json)을 함께 보존한다. 아래는 중단 전 실험 설계와 실행 방법의 보존 기록이다.

이 디렉터리는 이전 v1–v4와 독립된 실험이다. 목적은 공개 네트워크 흐름 데이터에서 Laya가 논문 모델과 비교군보다 탐지 성능과 처리 속도를 개선하는지 확인하는 것이다. **학습이 완료되기 전에는 우열 결론을 내리지 않는다.**

## 선택한 논문과 재현 범위

[FlowTransformer: A Transformer Framework for Flow-based Network Intrusion Detection Systems](https://arxiv.org/pdf/2304.14746v1), arXiv 2304.14746v1, 2023-04-28을 기준으로 한다. [저자 코드](https://github.com/liamdm/FlowTransformer)의 커밋 `52236c8c9feccdeb44acf578789db7b8b36bacea`를 고정했다. 2024년 저널 확장판의 결과와 혼용하지 않는다.

대상은 원문 Table III의 **UNSW-NB15 실험**이다. Shallow Encoder, Shallow Decoder, GPT Deep Decoder, BERT Deep Encoder의 각 2개 설정, 총 8개 설정과 Laya를 비교한다. 세 데이터셋 및 전체 하이퍼파라미터 탐색을 모두 재현한 것은 아니다. 논문에서 GPT·BERT라고 부르는 모델은 저자 코드로 초기화하는 구조이며, GPT 서비스나 사전학습 BERT 체크포인트가 아니다.

## 고정한 데이터와 평가 방식

- 데이터: UQ 공식 [NF-UNSW-NB15-v2](https://rdm.uq.edu.au/files/8c6e2a00-ef9c-11ed-827d-e762de186848), 2,390,275개 흐름.
- 공급자 BagIt SHA-1과 별도 SHA-256을 검증했다. CSV SHA-256은 `05019e3ac8d55b3f074f9f042623bbbb1af2527b8b78558c69353ccb2ccefa3f`이다.
- 학습 구간: 처음 2,151,248행. 평가 구간: 마지막 239,027행. 데이터의 행 순서를 유지한다.
- 학습 공격 78,782개, 평가 공격 16,271개. 마지막 흐름의 이진 공격 여부가 정답이다.
- 입력: 저자가 선택한 37개 특성, 연속 8개 흐름. IP 주소, 공격 이름, 정답 레이블은 입력에서 제외한다.
- 전처리: 학습 구간에서만 적합한 저자 구현. 수치 로그 정규화와 범주별 상위 32개 값. 원본 코드의 미지 범주 처리 동작도 보존한다.
- 학습: 배치 128개 중 공격 64개와 정상 64개, epoch당 64개 배치, 최대 20 epochs, 논문 코드의 학습 손실 기반 조기 종료. 세 seed의 표본 순서를 미리 생성하여 모든 모델에 동일하게 공급한다.
- **여기서 epoch는 8,192회 표본 추출이다. 학습 구간 215만 행을 한 번씩 모두 통과한다는 뜻이 아니다.** 전체 학습 구간에서 표본을 추출하는 저자 구현을 따른다.
- 판단 임계값: 공격 확률 `> 0.5`. 테스트 결과에 맞춘 임계값 조정은 하지 않는다.
- 반복: 모델 설정별 3회. 개별 값, 평균·표준편차와 논문 관행에 따른 최고 반복 값을 함께 보존한다. 주 결과는 조기 종료 또는 최대 epoch에서 얻은 마지막 체크포인트이다.
- 주요 지표: F1, 탐지율, 오탐률. 정밀도, 혼동행렬, PR-AUC, ROC-AUC, 공격별 탐지율도 저장한다.

정확한 실행 전 명세는 `protocol.json`에 있다. 논문 표와 **8개 설정 모두 파라미터 수가 일치**하며 `runs/architecture_audit.json`에 검증 결과를 저장한다. 입력 어댑터를 원본 pandas 처리 방식과 비교한 결과는 `runs/input_audit.json`에 저장한다.

고정 설정 BERT의 첫 반복이 정상 종료됐지만 탐지율 0%, 학습 손실 약 0.693을 기록하여 **추가 학습률 탐색**을 설계했다. 조건은 `sensitivity_protocol.json`에 별도 고정했다. 모든 비교 설정에 논문 Table I의 다섯 학습률을 각 3회 적용한다. 기존 0.001의 24회를 재사용하고 96회를 추가한다. 이 추가 설계는 사후 민감도 분석이며 Laya의 첫 평가 전에 확정했다. Laya는 사전에 선택한 0.00001의 3회 반복만 수행하므로 최적 Laya 또는 동일 탐색 예산 비교라고 주장하지 않는다. 최고 테스트 F1로 학습률을 선택하는 논문식 결과는 낙관적 선택임을 표시하고, 모든 학습률·실패·반복 값을 함께 제시한다.

## Laya 학습 조건

사용자 지정 모델 [convaiinnovations/laya](https://huggingface.co/convaiinnovations/laya)의 영어 기본 체크포인트와 원래 `noul` 이진 판정 헤드를 사용한다. 421,293,827개 파라미터를 가진 모델이며, 사용하지 않는 act 헤드를 제외하고 전체 파인튜닝한다. 별도 응답 생성 LLM은 이번 비교에 포함하지 않는다.

동일한 전처리 정보를 열 이름을 포함한 CSV 표로 직렬화한다. 수치는 float32를 복원할 수 있는 유효숫자 9자리로 표현하고, 범주 인덱스는 학습 시 확정한 대표 값으로 되돌려 표현한다. 테스트 레이블은 직렬화 경로에 전달하지 않는다. 표본 256개에서 입력은 1,417–2,008토큰이었다. 입력을 자르지 않으며, 실제 처리한 최대 길이도 기록한다. Laya의 기본 512토큰 설정은 이 입력에 충분하지 않으므로 상한을 8,192로 올렸다.

Adam 학습률은 처음부터 학습하는 비교군 0.001, 사전학습 Laya 0.00001로 고정했다. 둘 다 논문의 탐색 범위에 있지만, 논문은 설정별 최적 학습률을 공개하지 않았으므로 최적 하이퍼파라미터 탐색의 재현이라고 주장하지 않는다. Laya는 float32 가중치와 bfloat16 autocast, SDPA, gradient checkpointing을 사용한다. 물리 배치 8개를 누적해 유효 배치 128개를 구성하고 평가 배치는 16개다.

FlashAttention 실행 경로는 성능 점검만 했다. 기본 체크포인트의 학습 입력 16개에서 SDPA와 판정은 같았으나 최대 확률 차이 0.01774로 사전 검증 허용치 0.01을 넘었기 때문에 본 실험에는 채택하지 않았다. 이 점검에 사용한 가중치는 폐기했으며 학습 초기값에 사용하지 않는다.

## 원문과 일치하지 않거나 공개되지 않은 조건

원문은 90:10 분할을 명시하지만 공개 `main.py`의 UNSW 예제는 97.5:2.5를 사용한다. 본 실험은 원문 90:10을 우선한다. 따라서 본 실험 F1이 발표 수치를 넘더라도 그 사실만으로 논문을 능가했다고 해석하지 않는다. 비교의 근거는 **이번에 동일한 분할에서 다시 실행한 모델 간 결과**이다.

BERT는 첫 학습 단계의 XLA GEMM autotuning에서 TensorFlow 내부 비교 검사 오류로 중단됐다. 실패한 실행은 별도 보존하고, 두 BERT 설정의 모델 전체 JIT을 `jit_compile=False`로 해제하여 처음부터 실행한다. 이 변경은 결과를 본 뒤의 모델 조정이 아니라 컴파일러 오류의 우회이며 모델·optimizer·표본·epoch 설정은 같다. 추론 시간은 모든 비교군에서 공통의 표준 TensorFlow 호출 방식으로 측정한다.

원문의 Dense embedding 설명은 비선형 변환을 언급하지만 공개 구현은 `activation="linear"`이다. 이번 실행은 저자 코드를 따른다. 파라미터 수 일치는 구현 점검의 근거이며 원문과 모든 동작이 동일하다는 증명은 아니다. Adam의 epsilon도 프레임워크 기본값인 TensorFlow 1e-7, PyTorch 1e-8을 사용한다.

배치 128, epoch당 64개 배치와 window 8은 공개 예제에서 가져왔다. 첫 번째 Encoder 설정의 record embedding 차원 128은 논문 파라미터 수와 정확히 맞도록 복원했고, 다른 record 설정은 64, categorical embedding은 16이다. 원문에는 최적 학습률, seed, 정확한 평가 행 목록 등이 없다. 수치 특성 순서는 원본의 Python set 순서 대신 정렬하여 실행 환경 간 차이를 없앴다. 실행 환경도 원문의 Windows/Python 3.9/RTX 2070 Max-Q와 다르다.

## 해석에서 지켜야 할 한계

평가 구간 59,793개 흐름, 약 25.02%는 학습 구간에도 동일한 37개 입력 특성을 가진 행이 있다. 논문 분할 재현을 위해 제거하지 않았으며, 중복 포함 여부별 성적을 추가 산출한다. 이 중복 비율은 레이블을 제외한 특성 해시로 측정한 값이다. 같은 원본 연결이나 패킷이 중복 수집됐음을 확인한 것은 아니다.

v2 CSV에는 흐름 시작 시각이 없다. 이 실험의 ‘연속 8개’는 원본 행 순서이지 시간 간격·동일 호스트·다단계 공격 연쇄를 보장하지 않는다. 모든 공격 종류가 학습 구간에 포함되는 통상적인 지도학습 평가이므로, 이것만으로 **미학습 공격 탐지**를 입증할 수 없다. 또한 공격 확산 억제, QoS·라우팅·선택 차단·호스트 차단의 효과는 별도 네트워크 재생 실험이 필요하며 이번 이진 탐지 벤치마크의 결과와 구분한다.

## 실행과 산출물

서버 작업 디렉터리는 `/home/keinus/laya-security-lab`이다. 기존 v1–v4 파일을 수정하지 않는다.

```bash
.venv/bin/python v5/prepare.py
CUDA_VISIBLE_DEVICES=1 .venv-flow/bin/python v5/train_flow.py --inspect
.venv/bin/python v5/validate_inputs.py
.venv/bin/python v5/run_suite.py flow --gpu 1
.venv/bin/python v5/run_suite.py laya --gpu 0 --micro-batch 8 --eval-batch 16
```

위 학습 명령은 서버의 백그라운드 작업으로 실행한다. **상태를 확인하지 않고 중복 실행하지 않는다.** 완료된 실행은 자동으로 건너뛰며, 불완전한 비교군 디렉터리는 덮어쓰지 않는다. Laya는 epoch별 모델·optimizer·RNG 상태를 저장하여 `--resume`으로 이어갈 수 있다.

- `flow_worker.json`, `laya_worker.json`: 현재 실행, 완료 목록, 실패 상태.
- `grid_worker.json`: 비교군에 추가 적용하는 학습률 탐색 96회의 상태.
- `completion.json`: 전체 학습 후 동일 GPU 시간 측정·검증·결과 묶음을 순차 생성하는 단일 실험 작업의 상태.
- `runs/<model>/seed<seed>/training.json`: 완료가 검증된 학습 메타데이터.
- `runs/<model>/seed<seed>/running.json`: 진행 상태. 완료 결과로 취급하지 않는다.
- `predictions_epoch*_sequence.npz`: 평가 행 번호, 정답, 공격 확률 원본.
- `evaluation_epoch*_sequence.json`: 평가 지표와 공격별 탐지율.
- `data/prepared/manifest.json`: 전처리, 분할, 표본 스케줄, 해시, 중복 감사.

추론 시간은 학습이 끝난 뒤 같은 GPU에서 측정한다. 논문의 50개 무작위 배치·각 4회 반복·배치별 중앙값 후 평균 방식을 따르고, 배치 1의 직렬화·토큰화 포함 지연을 추가한다. 200ms 판정에 쓰는 p50/p95는 개별 요청 200개의 분포에서 계산하며, 반복별 중앙값 50개의 분포와 구분한다. window를 채우는 시간이나 네트워크 장비의 정책 적용 시간은 이 수치에 포함되지 않는다.

`finish_suite.py`는 핵심 27회 및 추가 학습률 탐색을 모두 마치면 9개 모델의 첫 seed를 같은 RTX 4090에서 순차 측정하고, `summarize.py`로 모든 정답·예측 파일의 지표를 재계산해 검증한다. 속도 표의 체크포인트는 고정 설정의 첫 seed이며 학습률 탐색의 최고값 체크포인트와 구분한다. 완료 전에는 `RESULTS.ko.md`를 만들지 않는다. 완료 시 이 결과 보고서와 `results_bundle.zip`을 생성한다. 블록 부트스트랩 구간은 고정된 체크포인트의 표본 불확실성을 살피기 위한 추가 분석이며, 모델 학습이나 임계값 선택에 사용하지 않는다.
